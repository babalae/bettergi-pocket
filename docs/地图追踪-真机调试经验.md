# 地图追踪真机调试经验

本文记录 Android 地图追踪调试中可复用的方法。PC 版提供路线、地图资源与导航算法参考；手机端的界面、手势时序和拾取位置必须单独验证。逐次测试报告、设备序列号、截图、录像和日志放在本地 `artifacts/`，不提交。

## 适用范围

当前标定来自联想 TB322FC、Android 16、3040×1904 横屏。已在真实采集路线验证目录选路、传送、连续转向、地面行走、精确接近和终点拾取。飞行、攀爬、其他分辨率及切到其他应用后的自动停止，仍需专项验证。

手机 UI 与 PC 不同，不能照搬 PC 的坐标、交互模板、角色编号或键盘操作。具体坐标以 `app/src/main/assets/pathing/layout.json` 为准，手机识别模板在 `app/src/main/assets/recognition/Pathing/`。

## 先确认设备、授权和画面

1. 在仓库根目录运行 `./tools/android-device.ps1 doctor`。ADB 不在 PATH 时，脚本会从 SDK 环境变量、`local.properties` 或默认安装目录寻找。设备必须显示 `device`；`unauthorized` 需要在已解锁设备上确认 USB 调试。
2. USB 已接通却看不到设备时，检查是否被 VMware 等虚拟机接管。在虚拟机的可移动设备菜单中断开平板，使其连接回 Windows 主机，然后重查 ADB；不必关闭虚拟机。
3. 用 `build` / `deploy` 构建并覆盖安装匹配 ABI 的 Debug 包。构建使用 Android Studio JBR 或合适的 JDK，避免误用系统 Java 8。覆盖安装保留数据，但会结束旧屏幕共享。
4. 用 `permissions` 启用无障碍，再用 `a11y-status` 确认 `connected=true`。设置列表中有服务不代表实际绑定；异常时关闭再开启该服务，并保留其他应用已有的无障碍设置。
5. 在悬浮窗开启共享屏幕，完成 Android 系统授权后，用 `status` 确认本应用的 MediaProjection 会话。仅打开共享开关不代表已经收到游戏帧。改变横竖屏或共享模式后重新截图，核对实际捕获尺寸。

完整命令见 [Windows 真机自动化](../tools/ANDROID-AUTOMATION.md)。本机坐标式系统弹窗脚本不作为通用工具发布，系统界面变化后需要重新观察。

普通截图使用设备端 `screencap -p` 后 `adb pull`，避免 Windows PowerShell 5 用文本重定向破坏 PNG。游戏画面通常没有可用的 UI XML；UIAutomator 在本机还会暂时抑制并重新连接应用无障碍，因此只在确实需要检查系统弹窗时使用 `capture -IncludeUiDump`，不要混入路线触控验证。

## 把设备操作和功能验证分开

运行 `connectedDebugAndroidTest` 前先备份设备上的应用数据。项目已设置 `android.injected.androidTest.leaveApksInstalledAfterRun=true`，保留测试后的应用安装；不要覆盖为 `false`，否则 Gradle 默认清理会卸载应用，并删除设置和已选路线。若临时指定参数，同样必须传入 `-Pandroid.injected.androidTest.leaveApksInstalledAfterRun=true`。

`adb shell input tap/swipe` 能证明 ADB 操作成功；功能验证要走应用自身的无障碍桥接和正式执行器。可先用 `a11y-tap` 验证打开、关闭大地图，再从悬浮窗选择并运行路线。

Debug 广播的 `gestureAccepted=true` 只表示手势已提交，不表示界面响应成功。广播仅返回 `result=0` 且没有状态数据时，也不能当作服务已连接。结合操作前后截图、执行日志和实际游戏结果判断。

前台状态是三态：`true`、`false`、`null`。游戏可能不发送预期的无障碍窗口事件，旧的设置页包名不能作为当前游戏在后台的证据。目前没有可用的使用情况记录时返回 `null`；这不等于已经确认在前台，也不等于无障碍未连接。前台检测和无障碍触控应分别报告，不能用手势成功代替前台检测通过。

## 连续触控的关键约束

`GestureComposer` 将摇杆、视角和瞬时拾取组成同一套触点。真机中最容易误诊为识别或超时的问题，实际来自触点续接：

- 续段起点必须等于上一段终点，且新笔画不能破坏续段开始时的触点数量。当前实现把新笔画放在第 1 ms 开始。
- 等上一段的 `onCompleted` 回调后再派发下一段。运行中的瞬时点按排队，持续触点位置更新合并；不能靠不断派发新手势抢占上一段。
- `willContinue` 的静止触点已经保持按下，不需要定时重复续接。本机的空续段会收到取消回调，错误重建多指后可能遗留注入触点，使后续 DOWN/MOVE 被系统拒绝。
- 不要把系统 `onCancelled` 当成单纯超时反复重试。检查 `BetterGI.Gesture` 日志及系统输入日志，确认有没有触点数量、续接起点或派发时序错误。
- 停止和异常退出都要释放持续触点、丢弃排队动作，并恢复悬浮窗穿透。停止线程带有中断位时，清理过程仍须能等待主线程完成释放，最后再恢复中断位。
- 任务开始前、路线切换和任务结束使用 `releaseAllAndWait`：最多等待 3 秒，以系统 `onCompleted` 确认抬手，记录不能在提交时提前删除。等待发生在工作线程/Binder 线程，不能阻塞回调所在的主线程；悬浮窗等抬手结果返回后再恢复触摸拦截。
- 清理被取消或超时不能当作成功，也不能把无效续接退化为新点按。无法确认释放时停止整个批次并提示重新开启无障碍，避免跳到下一条路线继续操作。该机制只处理本次服务仍记录的手势，不能保证清除进程崩溃前遗留、记录已丢失的系统注入触点；不调用 ADB、root 或特权注入接口。

修复后的验证顺序是：持续移动 → 移动中转向 → 移动中拾取 → 用户停止 → 再次点击小地图。最后一步能发现表面上已停止、实际仍残留触点的问题。人工触屏会取消自动手势，应在测试记录中注明，避免误归因。

## 视角与超时

在本机，10～30 像素的独立短滑可能被游戏忽略。连续修正应复用同一触点，使用 `dragBegin` / `dragStep` 累积位移；到达视角区边缘先抬起，再从中心开始下一段，不能按住手指直接回中，否则会反向转动。

读下一帧前等待滑动和游戏响应。当前转向每轮等待 80 ms 滑动加 50 ms 响应，默认允许 160 次尝试，另有取帧和识别耗时。手机慢可以放宽预算，但必须先区分手势被拒绝、画面未更新、角度判断错误和设备性能问题，不能只扩大超时掩盖故障。

## 坐标与小地图标定

坐标使用原生捕获帧的像素，不使用电脑预览窗口缩放后的像素。先核对 `referenceSize`、摇杆、视角区、按钮和拾取点，再运行路线。

小地图标定先固定圆心，扫描相邻的方形边长，裁剪后按算法需要缩放到 212×212，再比较匹配置信度和位置连续性。不要只选某一帧分数最高的参数；静止时定位应稳定，走动后位置变化应合理，旋转视角也不应造成位置跳变。本机小地图框为 `(123, 37, 420, 420)`。

模板阈值同时检查正样本和负样本，例如主界面派蒙对比大地图、传送按钮对比未打开传送面板的大地图。已有少量固定灰度裁图作为自动回归样本；完整截图只留本地。其他屏幕比例、UI 缩放和游戏设置需要重新核对，代码的坐标缩放不等于已经完成适配验证。

地区名单也是大地图的一种状态：打开后普通关闭按钮和设置齿轮会隐藏，需同时识别右侧“地图”标题与面板关闭按钮，不能仅凭通用叉号判断。名单已打开时直接识别目标地区，不再点击底下的区域按钮。TB322FC 的名单有两列，左列文字从屏幕约 61.7% 处开始；旧的 62% OCR 裁剪会切掉“挪德卡莱”的首字左侧。当前从 56% 处保留留白，地区名称去空白、规范异体字后匹配完整名称，允许同行附带图标文字。高亮状态实测 ML Kit 会读成“挪德卡菜”，按完整地名纠正，避免全局替换单字。回归见 `CountryRegionSelectorTest` 和 `PhoneMapTemplateTest`。

## 拾取位置、频率和终点收尾

手机可以点击物品交互条下方的一段空白区域来自动拾取。应在这段区域内标定稳定点，不能直接把物品条的位置作为通用点击点，也不能过低落到战技等按钮。本机原点 `(2083, 1526)` 上移约一个战技图标高度，当前为 `(2083, 1302)`。

当前拾取间隔为 200 ms，即每秒约 5 次。物品条可能延迟出现，多个物品也会逐次更新，所以一次点击成功不足以证明同一位置的物品已经拾取完。

普通路径点到达后立即报告整条路线完成，会漏掉终点物品。当前每个有行走点的路径段结束时，先释放移动和视角，停稳 300 ms，再按 200 ms 间隔拾取 2 秒；最后一次点按后也保留等待，之后才进入完成清理。用户手动停止会取消这段等待，不继续补拾。对应回归在 `EndpointPickupTest`。

验证终点时，分别观察“到达最后一个点”“停留拾取”“完成”三个时刻；画面应出现实际获得物品的提示。还要确认停止来自用户还是执行器自行结束，才能判断是否属于终点漏拾。

## 真机验证顺序与判据

1. 先测只读定位及单独的打开地图、转向、移动，确认坐标与触控正常。
2. 选一条短的、尚未采集的地面路线，覆盖传送、连续转向和行走。路线物品已采完就换路线，不把空场景当作拾取失败。
3. 专门检查途中拾取、多个物品、终点普通 `path` 点和停止清理。需要复现单个终点时，可在本地临时路线中保留该点，不修改原始路线资源。
4. 最后从正常悬浮窗目录选路再运行，避免只验证调试广播入口。调试文件路线覆盖只在当前服务实例内存中生效，结束调试后重启应用、恢复授权，再核对正常选择的路线。
5. 用新路线做最终回归。以物品消失及“获得 ×1”等提示确认真实拾取；不要把跟随宠物、角色动作、交互条出现或单纯靠近误认为已经获得物品。画面机制不明确时向用户确认。

日志中的“路线完成”只代表执行器走完流程，不能单独证明采集完整。最终结论必须写清验证范围；未遇到的飞行、攀爬、剧情和后台切换不能计入通过。

- 不提交：`artifacts/` 下的截图录像、逐次报告、设备状态、临时路线、标定探针、临时脚本及编译产物。
- 地图大资源、打包路线、路线索引和 `MANIFEST.txt` 由 `tools/sync-pathing-assets.ps1` 生成并忽略。校验清单用于本地核对来源，不携带本机路径和生成时间进版本库。
- 自动测试应读取随仓库提交的小型固定样本，不依赖某次测试时间或设备序列号目录。提交前检查 `git diff --check`、暂存文件清单和文件体积，并运行相关单元测试及 Debug 构建。
