## 0. 目标与原则

- 在 Pocket 中加入一个独立运行的「地图追踪」任务，执行 BGI 格式的路线 JSON，只支持材料采集，不含任何自动战斗。
- 移植的判定逻辑、常量、阈值、执行顺序与 BGI 保持一致。类结构可以重组。
- 必须改变的只有三类东西，全部在文中逐条标注为「适配」：
  1. PC 键鼠输入换成触控手势。
  2. PC 1080p 下写死的 UI 坐标换成手机参考画布坐标，用 `ReferenceSearch` 自动锚定换算。
  3. 依赖 PC 独有能力（鼠标中键视角回正、角色头像分类模型等）的功能，删除或降级。
- 每个移植的常量在代码里注明 BGI 源文件，便于对照。

## 2. 总体架构

```
悬浮窗「地图追踪」分组
  └─ PathingController（挂在 TriggerForegroundService）
       ├─ TaskGate：开始时暂停 TriggerEngine，结束时恢复
       └─ PathingTaskRunner（独立工作线程 "PathingWorker"）
            └─ PathExecutor
                 ├─ Navigation ── MiniMapLocator（锚定裁剪 + 二次缩放）
                 │              └─ MapManager ── TeyvatTemplateMatchMap / TeyvatMap（SIFT）
                 ├─ CameraRotateTask ── CameraOrientation（Calculator + Gia 兜底）
                 ├─ TrapEscaper
                 ├─ PartyControl（1–4 号位切人、E、出战角色识别）
                 ├─ ActionFactory（stop_flying / use_gadget / log_output …）
                 └─ TpTask ── BigMapTeyvat256Layer（SIFT）、TpPoints（tp.json）
            ↓ 逻辑动作（前进、转视角、跳、E、Z、切人、点击、拖图…）
       GameInput（逻辑动作 → 原生屏幕坐标的触控指令）
            ↓ ContentProvider 桥（已有）
       InputAccessibilityService（:a11y 进程）
            └─ GestureComposer：持续触点（摇杆、长按）+ 瞬时手势合并派发
```

## 3. 坐标与缩放体系（需求 4）

### 3.1 三个坐标空间

| 空间 | 定义 | 用途 |
|---|---|---|
| N：原生屏幕 | 设备分辨率 W×H | 截图、触控 |
| R：手机参考画布 | 标定时所用截图的分辨率（大概率与 AutoSkip 相同，为 3040×1904） | 所有手机 UI 位置和模板 |
| P：PC 1080p 标准 | BGI 的识别空间 | 匹配算法的输入尺寸、与画面内容尺度相关的 PC 常量 |

换算：

- **R → N（UI 位置）**：复用 `ReferenceSearch`。`s = min(W/refW, H/refH)`，锚点按 `SearchAnchorMode.Auto` 由 bbox 中心决定（<0.4 靠左/上，>0.6 靠右/下，其余居中）。已新增 `ReferenceSearch.mapReferenceRect`，公式与 `tryGetRegion` 相同但不外扩，供按钮坐标、ROI 等非模板场景使用。
- **N → P（画面内容尺度）**：`k = min(W/1920, H/1080)`，与 BGI `SystemInfo.ScaleTo1080PRatio` 相同。它和现有 `CaptureScale` 的「按 1920 宽缩放」不同，20:9 屏上两者结果不一样。地图追踪统一用 `k`。

PC 常量按性质分两类处理：

- UI 位置类（小地图位置、大地图左上角遮挡区 360×430、区域切换按钮 `(cw-160s, ch-60s)`、重叠列表 ROI `rect(1270s,100s,50s,H-200s)`、缩放滑条 Y 范围 468–612、队伍槽位等）：在 R 上按手机截图重新量取，经锚定换算。
- 内容尺度类（`MapScaleFactor=2.361`、拖图每步 48 px、`Tolerance=200`、`MapZoomOutDistance=1000`、图标对齐的 60/14/16 px 等）：数值不变，乘 `k` 换到 N。

### 3.2 小地图：锚定裁剪 + 二次缩放（已实现）

BGI 的小地图输入是 1080p 截图中 `Rect(62, 19, 212, 212)` 的 BGR 图（`MapAssets.MimiMapRect1080P`）。TemplateMatch 取中心 156×156，SIFT 和视角计算用整张 212×212。手机流程（`MiniMapLocator`）：

1. **锚定定位**：标定数据在 `assets/pathing/layout.json` 的 `miniMap.bbox`（R 坐标），为小地图外接正方形：边长 = 手机小地图圆直径 × 212 / PC 1080p 小地图圆直径，中心取圆心，使它与 PC 的 212 ROI 覆盖同样的画面范围。锚点默认 Auto，会解析为左上。
2. **二次缩放**：从原生帧裁出正方形 ROI，缩放到 212×212（缩小用 `INTER_AREA`，放大用 `INTER_CUBIC`）。输出与 BGI 1080p 下 `new Mat(SrcMat, MimiMapRect)` 尺寸和尺度一致。
3. 同一帧只裁一次，结果同时给 `Navigation`（定位）和 `CameraOrientation`（视角）。BGI 在同一帧上各裁一次，结果相同。

待标定后决定的事项：

- **精定位**：TB322FC 3040×1904 的 212 裁图已确认盖住小地图，这台设备不再外扩、也不再用外框模板找圆心。其他比例的屏幕如果发现偏移，再按这个办法补。
- **世界尺度**：前提是手机小地图显示的世界范围与 PC 相同。需要用已知坐标的手机截图验证；不同时在步骤 2 引入固定的「小地图世界尺度修正系数」调整裁剪边长。

BGI 在低于 1080p 时不缩放 ROI（例如 1600×900 下 ROI 只有 177 px，仍然裁 156 px，尺度是错的）。Pocket 总是输出 212，不复现这个问题。

### 3.3 大地图（传送用 SIFT，匹配部分已实现）

- BGI：整帧灰度（1080p 归一化后）→ 缩小到 1/4 → 与 `Teyvat_0_256_SIFT` 匹配。
- Pocket：整帧灰度 → `k > 1` 时除以 `k` 缩到 P 尺度（`k < 1` 时不放大，与 BGI 一致）→ 交给 `SceneMap.getBigMapPosition / getBigMapRect`（内部 1/4 缩放与 BGI 相同）。前一步由传送任务负责。
- 点击坐标用 BGI 的比例投影 `clickX = (picX - picRect.X) / picRect.W × captureW`，与分辨率无关，直接得到 N 坐标。
- `MapScaleFactor=2.361`（缩放 1 级时每游戏单位对应的 1080p 拖动像素）需要在手机上实测一次。若手机大地图的内容尺度与 PC 按屏幕高度等比，数值不变；否则作为标定常量写入布局文件。

### 3.4 UI 模板识别

手机 UI 模板全部放 `recognition/Pathing/`，走现有 `RecognitionObject` + `ImageRegion` + `ReferenceSearch`。模板是手机参考截图上的原尺寸裁剪，运行时按 `s` 缩放，与 AutoSkip 相同。

## 4. 模块设计

### 4.1 路线模型与解析

- 用 `org.json` 解析（项目已在用），字段为 snake_case：`info`、`config`、`positions`。
- `info`：`name`、`type`、`map_name`（默认 Teyvat）、`map_match_method`（默认 TemplateMatch）、`bgi_version` 等。
- `positions[]`：`x`、`y`（游戏坐标）、`type`（path / target / teleport / orientation）、`move_mode`（walk / run / dash / climb / fly / jump / swim）、`action`、`action_params`、`point_ext_params.misidentification`（`type` 默认 `["unrecognized"]`，`handling_mode` 默认 `previousDetectedPoint`）。
- `WaypointForTrack`：保留原始 `GameX/GameY`，`X/Y` 换成地图图像坐标：`imgX = 32768 - 2·gameX`，`imgY = 24576 - 2·gameY`（`SceneMap.convertGenshinMapCoordinatesToImageCoordinates`）。
- 分段：遇到 `teleport` 点就开新段，传送点作为新段的第一个点。
- `ActionEnum` 完整保留，包括每个动作的强制点位类型（`UseWaypointTypeEnum`），保证 `IsTargetPoint` 判定和 BGI 一致。
- 执行前校验（任一不满足则整条路线拒绝执行，并提示原因）：
  - `map_name` 必须是 Teyvat。
  - 所有点的 `action` 都在 4.7 的支持列表内。

### 4.2 PathExecutor

主循环（与 BGI 一致，删除项已标出）：

1. 路线没有点：结束。
2. ~~切换队伍~~、~~队伍识别与角色校验~~（删除）。
3. 转换并分段，`delay(100)`，`Navigation.warmUp(map_match_method)`（加载地图数据）。
4. 每段最多重试 2 次（`RetryTimes = 2`）：
   - `ResolveAnomalies()`。
   - 首点不是传送点时 `Navigation.setPrevPosition(首点)`。
   - 逐点执行：`TryCloseSkipOtherOperations`；~~`RecoverWhenLowHp`~~（删除）。
     - 传送点：不是第一段，且上一段末点不是传送点、也不是 fight / nahida_collect / pick_around 时，先 `delay(1000)`；然后 `TpTask.Tp(...)`；`setPrevPosition(传送点图像坐标)`；`delay(500)`。
     - 其他点：`BeforeMoveToTarget` → 方位点 `FaceTo`，非 `up_down_grab_leaf` 时 `MoveTo` → `BeforeMoveCloseToTarget` → 目标点 `MoveCloseTo` → 有动作且未处于跳过状态时 `AfterMoveToTarget`。
   - 异常：`HandledException` 放弃本段；`NormalEndException` / 取消放弃本段；`RetryException` 记录恢复点后重试；`RetryNoCountException` 重试且不计次数。
   - `finally`：松开所有触点（对应 BGI 松开 W、右键、普攻）。
5. 返回 `PathingResult(isSuccess, 首个失败原因)`。

`MoveTo`（常量全部照搬）：

- 开始时不再切人。手机分不出号位，行走位已删除。取一次位置，`WaitUntilRotatedTo(目标朝向, 5)`。
- 按住前进（摇杆推满向前）。每帧开头检查摇杆是否仍按住，没有就补按。
- 超过 240 秒抛 `RetryException`。
- 距离 < 4（图像像素，等于 2 个游戏单位）视为到达。
- 距离 > 500：累计次数，超过 50 次抛 `HandledException`；每 5 次打日志；每 10 次调用 `ResolveAnomalies`、把上一个距离正常的位置设为 prev、`delay(500)`；每次 `delay(50)` 后 `continue`。（BGI 先检查暂停点，暂停已删除，这个分支不再触发。）
- 非攀爬模式下卡死检测：每隔 `1000 + additionalTimeInMs` 毫秒记一次位置，记满 8 个后，若第 8 个与第 1 个的 |dx|+|dy| < 3，`_inTrap++`；超过 2 次抛 `RetryException`，否则执行 `TrapEscaper.RotateAndMove()` 和 `TrapEscaper.MoveTo()`。
- 视角：`RotateToApproach`。进入 2 秒后且第 5 帧起，偏角 > 5° 连续 3 帧以上且持续超过 2 秒时，松开摇杆、`WaitUntilRotatedTo(目标, 2)`、再按住。
- 移动模式：
  - fly：没处于滑翔状态就点跳，`delay(200)`；`delay(100)` 后 `continue`。
  - jump：点跳，`delay(200)`，`continue`。
  - run：距离 > 20 时按住冲刺，≤ 20 时松开。
  - dash：距离 > 20 且距上次 > 1000 ms 时点一次冲刺。
  - 其余（非 climb）：
    - 自动冲刺：距离 > 20 且距上次 > 2500 ms 时点一次冲刺。生存位和按号位放 E 已删除。
- 自动按 Z：间隔 > 0 且距上次超过间隔时点小道具按钮。
- 拾取（适配，见下）：距上次拾取超过间隔时点一次拾取位置。
- 帧尾 `delay(100)`。退出循环后松开摇杆。

**拾取（适配）**：BGI 跑路线时开着 AutoPick 实时任务（识别 F 提示后按 F）。手机上点空白处即可拾取周围全部物品，所以地图追踪内部每走一段时间点一次「血条右上方」的位置，不依赖实时任务：

- 位置：标定在 `layout.json`（R 坐标）。TB322FC 上拾取点在元素爆发与元素战技的空隙正中，再往上一个爆发按钮的高度。
- 间隔：沿用 AutoPick 的 800 ms（`AutoPickFeature.CLICK_INTERVAL_MS`）。
- 时机：`MoveTo` 循环中按间隔点击；`MoveCloseTo` 到达后点一次。点击与摇杆按住合并派发（5.2）。

`MoveCloseTo`：最多 25 步；每步取位置，距离 < 2 结束；`WaitUntilRotatedTo(目标, 2)`；摇杆向前点 60 ms；`delay(20)`。结束后松开，`delay(1000)`。

`FaceTo`：取位置，`WaitUntilRotatedTo(目标, 2)`，`delay(500)`。

`WaitUntilRotatedTo`（执行器包装）：失败时 `ResolveAnomalies()` 后再试一次。

`GetPositionAndTime`：

1. `Navigation.getPosition(当前帧的小地图)`。
2. 结果为 (0,0) 且不在主界面：`ResolveAnomalies(当前帧)`。
3. 识别失败处理：结果为 (0,0) 且 `misidentification.type` 含 `unrecognized`，或距离 > 500 且含 `pathTooFar` 时生效。
   - `previousDetectedPoint`：用上一次位置。
   - `mapRecognition`：打开大地图，`GetPositionFromBigMap`，关闭地图，`WaitForCloseMap(10, 200)`，耗时作为 `additionalTimeInMs` 返回。
4. 其余情况记录为上一次位置。

`ResolveAnomalies`：

1. 识别到烹饪页、各类关闭按钮（BGI 的 Cook / PageCloseMain / PageClose / PageCloseWhite）且不在大地图：点关闭按钮（适配：BGI 按 ESC），`delay(1000)`。
2. ~~月卡弹窗~~（不做）。
3. 自动跳过剧情（固定开启）：检测到对话界面时进入循环，每帧 `delay(210)`，连续 10 帧以上不在对话界面时退出。对话识别复用 Pocket 现有 AutoSkip 的识别对象；选项选择按 BGI 地图追踪的规则「优先选最后一个选项」，不沿用 Pocket 实时任务「选最上面一个」的规则。

### 4.3 Navigation 与地图匹配（已实现）

`Navigation` / `NavigationInstance`：

- 状态：`prevX = prevY = -1`、`captureTime`。
- `getPosition`：本地匹配（有 prev）或全局匹配（prev = -1）。成功且帧时间更新时更新 prev。TemplateMatch 本地失败不回退全局，由执行器处理。
- `getTargetOrientation`：`angle = acos(dx/len)`，`dy < 0` 时取 `2π - angle`，转为整数度。`getDistance` 为欧氏距离（图像坐标）。

`MapManager`：缓存键 `"{map}_{method}"`。`SIFT` → `TeyvatMap`，其余 → `TeyvatTemplateMatchMap`（BGI 的 `TeyvatMapTest`，默认）。
提瓦特常量：块宽 2048，19 行 22 列，原点 (32768, 24576)，图像/游戏比例 2。图像坐标 (0,0) 转游戏坐标时返回 null。

**TemplateMatch（默认路径）**：

- 常量：`OriginalSize=156`、`RoughSize=52`、`ExactSize=260`、`RoughZoom=5`、`ExactZoom=1`、`RoughSearchRadius=50`、`ExactSearchRadius=20`、置信度阈值 `{0.99, 0.97, 0.95}`。
- 预处理：`MaskCalculator.process1`（取中心 156、生成图标掩膜）→ `CameraOrientationCalculator.predictRotation` → `process2(angle)`（去暗角、去视野扇区、边界掩膜、圆形掩膜）。LUT、扇区 ±45.5°、颜色阈值全部照搬。
- `MatchContext`：粗匹配 52×52（`INTER_AREA`，掩膜 `INTER_NEAREST`）；精匹配灰度 260×260（`INTER_CUBIC`）。
- `FastSqDiffMatcher`：用 CCORR 拼出带掩膜的 SSD，`minVal + TplSumSq` 送入归一化器。
- `TemplateMatchNormalizer`：SqDiff 模式，置信度 `1 - SSD/worst`。
- `SubPixMatch`：3×3 二次曲面拟合，偏移限制在 ±1。
- 图层几何：`WorldToMap`、`MapToWorld`、`GetRect`。粗匹配窗口 ±50·Scale（彩图像素），精匹配窗口 ±20（灰度图像素）。
- 搜索流程：全局粗匹配遍历所有图层；本地粗匹配在 prev 恰好等于上次成功结果时先试上次的图层（置信度 ≥ 0.99 即停），否则遍历其他图层；粗匹配置信度 ≥ 0.95 才做精匹配；最终阈值 0.95。
- 图层加载：`Map/Teyvat/` 顶层全部 `*.json`（按文件名排序，与 Windows 枚举顺序一致）→ 每项读 `{LayerId}_color.webp`（BGR）和 `{LayerId}_gray.webp`（灰度，`IsOverSize` 时为 png）。

**SIFT 路径**：

- `SIFT.create()` 默认参数；匹配器 BruteForce 与 FlannBased。
- `knnMatch`：k=2，比值 0.75，好匹配 ≥ 7，`findHomography(RANSAC, 3.0)`，投影查询图中心。
- `match`（大地图无先验时）：FLANN `match`，保留距离 < max(2·最小距离, 0.02) 的匹配，RANSAC，投影中心。
- `knnMatchRect`：投影查询图四角，取外接矩形。
- 小地图本地搜索：1024 px 分块，`chooseBlocks` 取 3×3 邻域（BruteForce），失败不回退全局。
- 大地图本地搜索：256 图层按 76×88 分块，`buildLocalSearchRect` + `knnMatchLocal`（外扩 2 块），失败回退全图 `match`。
- 特征文件：`.kp.bin` 为无头 `cv::KeyPoint` 数组（每条 28 字节，小端），只读取 pt.x / pt.y；`.mat.png` 为 128 列 8 位灰度 PNG。

C# 与 Kotlin 的语义差异统一处理：`Math.Round` 是银行家舍入，用 `csRound`（`Math.rint`）；`(int)` 强转对应 `toInt()`（都向零截断）；整数除法保持整数；`Point2f` 相等按 C# `float.Equals`；时间用 `System.nanoTime()`。

### 4.4 视角

- `CameraOrientation.computeMiniMap`（已实现）：对 212×212 小地图调用 `CameraOrientationCalculator.predictRotation`；置信度 < 0.2 时用 `CameraOrientationFromGia` 兜底。两套算法常量照搬（`TplOutRad=78`、`TplInnRad=19`、`RLength=60`、`PeakWidth=181` 等）。`MaskCalculator` 和 `Calculator` 持有可变缓冲区，定位和视角各用一套实例，与 BGI 一致。
- `RotateToApproach`：`diff = (cao - target + 180) % 360 - 180`，小于 -180 时加 360；增益 |diff| > 90 取 4，> 30 取 3，> 5 取 2，否则 1。
  - 适配：BGI 输出鼠标横移 `-ratio·diff·dpi` 像素。Pocket 输出右侧视角区的横向滑动 `-ratio·diff·c` 像素，`c` 的测定方法见第 13 节。
- `WaitUntilRotatedTo(target, maxDiff, maxTryTimes = 50)`：每次 `delay(50)`。

### 4.5 传送 TpTask

流程与常量照搬（`TpTask.cs`）：

- `Tp`：60 秒超时，`TpWithRetries` 最多 3 次。面板未打开：关闭地图后直接抛出；传送点未激活：关闭面板后重试；其他异常：`delay(300)` 后重试。
- `TpOnce`：打开大地图（最多等 63 次 × 80 ms，失败则回主界面再试一次）→ 切回地表图层（最多 38 次 × 80 ms）→ 取最近的 2 个传送点 → 选地图区域 → 准备可点击视野（最多 5 次）→ 点击图标（绝对图标对齐）→ 等面板并确认 → 等加载完成。

- 拖图 `MoveMapToCore`：最多 30 次迭代，惯性预测 `center + sent·zoom/2.361`，本地 SIFT 校正，异常跳变判定（跳变 > max(200, 2·期望)，或期望 > 1200 时比例超出 [0.55, 1.85] 或方向余弦 < 0.65），连续失败 > 5 次抛出。
- 拖动手势 `MouseMoveMap`：边缘留白 115、起点抖动 ±W/24、避开左上 UI 区、步数 `clamp(ceil(len/48), 5, 60)`、前 42% 的步走完 85% 距离、剩余按余弦权重减速，每步 20 ms，松手前停 60 ms。
- 缩放：读数公式 `zoom = 6 - 5·(612 - y)/(612 - 468)`（y 为滑块中心，P 坐标）；调整循环保留「测量 → 校准 → 判断接近 → 连续 2 次无进展退出」。

- 面板：先等 `max(200, …)` ms，再每 80 ms 轮询。识别到传送按钮即确认；否则识别重叠列表候选（图标模板 + 右侧 220 宽 HLS 白字 OCR），按与 tp.json 名称的字符重合数选择，最多点 2 次。

### 5.2 手势合并

Android 的 `dispatchGesture` 会取消本服务正在进行的手势，所以「按住摇杆的同时转视角、点 E」必须合并派发：

- `GestureComposer` 运行在 `:a11y` 进程，维护持续触点（摇杆、冲刺按住、E 长按）。持续触点用 `StrokeDescription(willContinue = true)` 分段，后续派发用 `continueStroke` 续上。系统（`MotionEventInjector`）的约束：续段起点必须与上一段终点完全相同；续接手势第 0 ms 的触点数必须等于未结束的触点数，所以新笔画从第 1 ms 开始；续接手势排在已排期事件之后，所以按住段只有 30 ms，位置没变时不重复派发。`willContinue` 笔画结束后触点保持按下，没有超时。
- 每次瞬时手势（点按、滑动）派发时，把所有持续触点的续段和瞬时笔画放进同一个 `GestureDescription`，数量不超过 `getMaxStrokeCount()`。
- 注册 `GestureResultCallback`，被取消（例如用户手动触屏）时重建持续触点。
- 桥接口在 `handleBridgeCall` 中新增：`pad.hold(angle, magnitude)`、`pad.release`、`button.down/up`、`tap`、`swipe`、`drag.begin/step/end`、`releaseAll`。坐标一律为 N。
- `continueStroke` 需要 API 26。地图追踪功能要求 Android 8.0 以上，minSdk 24/25 的设备上隐藏入口。

### 5.3 悬浮窗与注入手势的冲突

注入的触点如果落在悬浮窗上会被悬浮窗吃掉。运行期间面板收起成悬浮球，悬浮球移到不与任何游戏按钮、摇杆、视角区重叠的位置，并且只响应「点击停止」。

## 6. 独立任务与实时任务（需求 3）

- `TaskGate.exclusiveRunning`：地图追踪开始时置位，`TriggerEngine` 的 tick 检查到置位就直接跳过（不取图也不丢帧，300 ms 后再检查），保证实时任务不和地图追踪抢帧。

- 取图能力保留：屏幕共享和 `ScreenCaptureController` 保持运行，由地图追踪独占取帧。
- 取帧新鲜度：BGI 每次 `CaptureToRectArea()` 都拿最新画面。Pocket 的 `acquireLatestBgr()` 在没有新帧时会复用最多 2.5 秒前的缓存帧，这对定位和转视角闭环是错误输入。给 `CapturedBgrFrame` 加帧序号，地图追踪取帧时要求序号比上次大，最多等 500 ms，超时视为本帧识别失败。
- 启动前检查：屏幕共享已开且在出帧、无障碍服务已连接、原神在前台、Android ≥ 8.0、`layout.json` 已标定。
- 停止来源：用户点停止、屏幕共享停止、无障碍断开、原神离开前台。停止后抬起所有触点、恢复实时任务、调用 `Navigation.release()` 释放地图数据。

## 13. 视角滑动灵敏度的测定

BGI 的转向是比例控制：每帧鼠标横移 `-ratio·diff·dpi` 像素，游戏再按「每鼠标像素多少度」转视角。设 PC 上每鼠标像素对应 q_pc 度，则每帧实际转过 `ratio·diff·q_pc` 度。手机上设每滑动像素对应 q_m 度，要让每帧转过的角度相同，滑动像素应为 `ratio·diff·c`，其中 `c = q_pc / q_m`。增益表（4/3/2/1）和阈值都不变。

q_m 与设备分辨率、游戏内「镜头灵敏度」设置都有关，因人而异，建议做成任务开始前的自动标定（结果按分辨率缓存，用户改了灵敏度时可手动重新标定）：

1. 在主界面空旷处站定，连续取 3 帧，用 `CameraOrientation.computeMiniMap` 求视角，取中位数 θ0。
2. 在视角区中部做一次水平滑动 d 像素（原生坐标）：匀速约 300 ms，终点原地停留 ≥ 100 ms 再抬起，避免甩动带来的惯性。
3. 等 300 ms 画面稳定，再取 3 帧求 θ1。Δθ = θ1 − θ0，换算到 (−180°, 180°]。
4. d 取 ±100、±200、±400 px，每个做 2 次。对 (d, Δθ) 做过原点的最小二乘：q_m = Σ(d·Δθ) / Σd²。
5. 检查线性：各点残差 < 2°，左右两个方向的斜率相差 < 10%，换一个滑动速度结果一致。不满足说明有加速度或惯性，需要改成分段滑动后重测。

符号：视角角度在图像坐标系下顺时针增大，向右滑视角右转、角度增大，与 BGI 鼠标右移一致，标定结果自带符号。

q_pc：用 BGI 在 PC 上按同样方法测一次（`MoveMouseBy(dx, 0)`，dx 取 ±200～±800，游戏灵敏度为默认值），作为常量写进代码。BGI 本身不标定 PC 灵敏度，说明这个闭环对增益的偏差有一定容忍度，q_pc 只需测一次。

滑动幅度限制：单次滑动不能超出视角区。计算出的像素超出时按视角区宽度截断，剩余部分下一帧继续，闭环会自动收敛。

### 14.3 与 BGI 的结构差异（结果不变）

- 输入是 `MiniMapLocator` 输出的 212×212 小地图，而不是整帧。
- SIFT 特征点只存坐标；描述子以 8 位常驻、按需转 float（PNG 中本来就是 0～255 的整数）；切块时不再复制描述子（BGI 中块内副本从未被读取）。
- `FastSqDiffMatcher` 不再常驻 float 平方图，匹配时对搜索区域现算（省约 240 MiB）。
- 精匹配灰度图改为按需解码，按 256 MiB LRU 淘汰（BGI 全部常驻约 500 MiB）。首次进入某个图层多一次解码耗时。
- 未移植 BGI 中未被调用的代码：`RoughMatchLocalChan` 及其归一化器、`GetBigMapRect(grey, prevRect)`、其他场景的 `ExtractAndSaveFeature`。
- `TemplateMatchNormalizer` 的 CCoeff 分支按 float 正确读取（BGI 用 `At<double>` 读 CV_32F，该分支在地图追踪中不会用到）。

PC（JVM）实测：TemplateMatch 图层加载 0.3 s，全局匹配约 0.7 s，局部 3～11 ms；SIFT 2048 加载 0.7 s，局部 7～27 ms，全局约 4.8 s。
